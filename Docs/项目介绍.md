# SimplenessAgent 项目介绍

## 一句话介绍

SimplenessAgent 是一个面向本地与 API 模型的可靠任务执行型 Agent 框架：模型负责提出方案和生成候选动作，程序负责计划校验、状态迁移、权限、证据、审计与恢复。

## 为什么做这个项目

多数 Agent 工具把聊天消息当作系统真相，容易出现上下文膨胀、计划不可复用、工具副作用不可追踪和任务中断后无法安全恢复等问题。SimplenessAgent 将以下对象作为第一等公民：

- **Task**：目标、约束、验收条件与预算。
- **Plan / Step**：可校验、版本化的执行 DAG，而非单段自然语言计划。
- **Event / Checkpoint**：可重放的运行事实和恢复边界。
- **Artifact / Evidence**：可验证的产物及其完成依据。
- **Tool / Policy**：受工作区、能力、风险和审批约束的确定性动作。

## 目标用户与场景

首期服务需要在个人电脑上运行本地 Qwen 或接入远程 API 的开发者。典型场景包括：阅读和分析代码库、定位问题、生成可审阅的计划、修改有限文件、运行测试、保存证据并在重启后恢复任务。

项目将以 `Qwen3.6-35B-A3B` 一类本地可运行模型为重要验收对象，但不会把任何模型、Thinking 格式或 Provider 协议硬编码进 Agent Core。

## 核心原则

1. **确定性外壳，概率性内核**：模型不能直接改变任务状态或绕过权限。
2. **计划与证据优先**：复杂任务先形成并校验 Plan；没有 Evidence 不自动完成。
3. **原始事实不可变**：事件和 Artifact 追加保存，摘要、记忆和索引可重建。
4. **本地优先，统一契约**：本地模型和 API 模型使用同一个 Agent Core。
5. **安全默认拒绝**：工作区越界、未经批准的副作用和缺失隔离能力均 fail-closed。
6. **界面不是事实来源**：未来桌面端只通过应用服务、快照和事件流呈现与控制任务。

## 当前基础框架

`CLI → App Service → SQLite Event Store → Plan DAG → Workspace-bound Tool → Artifact + Evidence → Checkpoint`

当前实现刻意只开放确定性的工作区侦察闭环，用于验证数据模型、状态机、持久化与恢复链路。模型驱动执行、写工具、真实 Provider、上下文系统、记忆、Skill、多 Agent 和桌面体验将在该基础上迭代，并且每项能力必须有契约、测试和可追溯状态。
