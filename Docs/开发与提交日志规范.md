# SimplenessAgent 开发与提交日志规范

## 1. 目的与适用范围

本规范约束代码提交、变更日志、运行日志与安全审计记录。目标是让每项变更可追溯、可审阅、可验证，且不让日志泄露密钥、隐私或模型隐藏推理。

适用于主仓库、未来插件仓库、CLI、桌面端、迁移脚本、Prompt、评测集和文档。

## 2. 提交信息规范

使用 Conventional Commits：

```text
<type>(<scope>): <简短中文说明>

[可选正文：说明动机、影响范围、风险与验证方式]

[可选页脚：BREAKING CHANGE: <迁移说明>]
```

### Type

| Type | 使用场景 |
|---|---|
| `feat` | 对用户或调用方可见的新能力 |
| `fix` | 修复缺陷或安全问题 |
| `refactor` | 不改变外部行为的结构调整 |
| `test` | 新增或调整测试、Fixture、Golden Case |
| `docs` | 文档、ADR、项目介绍、规范更新 |
| `build` | 构建、依赖、打包、CI 或工具链变更 |
| `perf` | 有基准数据支撑的性能优化 |
| `chore` | 无产品行为影响的维护事项 |
| `revert` | 撤销既有提交 |

### Scope

优先使用稳定模块名：`contracts`、`storage`、`task`、`plan`、`tool`、`policy`、`provider`、`artifact`、`workspace`、`cli`、`ui`、`docs`、`eval`、`migration`。

示例：

```text
feat(storage): 增加任务事件与物化状态原子提交
fix(tool): 阻止 Windows 重解析点越过工作区边界
test(recovery): 覆盖工具执行后进程终止场景
docs(adr): 记录 Artifact 内容寻址决策
```

### 提交要求

- 一个提交只解决一个可审阅的目的；不要混入格式化、无关重构或生成文件。
- 行为变更必须同时更新测试；协议或数据库变更必须更新契约、Migration 和兼容性测试。
- 架构决策先写 ADR，再提交实现。
- 提交正文应注明验证命令与结果；无法运行的检查要写出原因和替代验证。
- 禁止提交 API Key、Token、密码、个人隐私、真实生产日志或模型隐藏推理。

## 3. CHANGELOG 规范

- 根目录 `CHANGELOG.md` 是面向使用者的版本变更记录。
- 每个版本使用 `新增`、`变更`、`弃用`、`移除`、`修复`、`安全` 分类；没有内容的分类不创建。
- `Unreleased` 只记录已合并但未发布的用户可见变化，不复制每个内部提交。
- 破坏性变更必须包含迁移步骤、受影响协议版本和回滚说明。
- 发布前由维护者确认版本号、发布日期、比较链接、验证结果和升级路径。

## 4. 应用运行日志

采用 JSON Lines，统一字段如下：

```json
{
  "timestamp": "2026-08-11T00:00:00Z",
  "level": "INFO",
  "event": "tool.call.completed",
  "component": "tool",
  "task_id": "tsk_xxx",
  "run_id": "run_xxx",
  "step_id": "stp_xxx",
  "correlation_id": "corr_xxx",
  "message": "只读文件列表已生成",
  "duration_ms": 123
}
```

规则：

- 时间统一使用 UTC RFC 3339 Nano；字段名使用 `snake_case`。
- `level` 仅使用 `DEBUG`、`INFO`、`WARN`、`ERROR`；不要把失败伪装成 `INFO`。
- `event` 使用 `<component>.<noun>.<verb>`，例如 `task.status.changed`、`provider.request.failed`。
- Task、Run、Step、ToolCall、Artifact 使用稳定 ID，不使用可变标题作关联键。
- 长输出写入 Artifact，日志只记录摘要、大小、哈希和引用。
- 模型或工具输出一律视为不可信数据，不能作为日志控制字段。

## 5. 安全审计与脱敏

以下操作必须写入结构化审计事件：权限请求/决定、危险或外部副作用工具调用、越界访问尝试、凭据使用、Sandbox 不可用、MCP/Skill 安装、数据删除与导出。

- API Key、密码、Cookie、授权头、私钥和用户敏感文件内容禁止写入日志、Artifact、诊断包或模型上下文。
- 仅记录凭据引用、脱敏指纹或使用结果，绝不记录明文。
- Tool Intent、审批票据、执行结果和幂等键必须可关联，但审批票据仅匹配已规范化的参数哈希。
- 原始隐藏推理不属于任务事实，不持久化到运行日志。

## 6. 变更前检查清单

- [ ] 目标、输入输出和失败后果已明确。
- [ ] 契约、错误码、状态和事件版本已评估。
- [ ] 需要时已新增 ADR 和 Migration。
- [ ] 单元/契约/集成/恢复测试已运行，结果写入提交正文或 PR。
- [ ] `CHANGELOG.md` 已更新（若存在用户可见变更）。
- [ ] 无密钥、缓存、数据库、构建产物或不相关文件进入暂存区。
