# SimplenessAgent 详细开发策划案

## 1. 开发总策略

项目采用“契约优先、纵向闭环、逐步增强”的方式开发。

不先铺满全部模块骨架，而是先完成一条可以运行、验证、恢复的最小任务链，再逐步增加记忆、多 Agent、桌面产品和生态。

开发优先级：

1. 协议正确性。
2. 状态持久化和恢复。
3. 工具安全与验证。
4. 小模型上下文和规划。
5. 多 Agent。
6. UI 丰富度和生态扩展。

## 3. 开发过程标准

每个功能按照以下顺序开发：

1. 明确用户价值和失败后果。
2. 定义输入、输出、状态和错误码。
3. 确定是否需要 ADR。
4. 编写契约测试和失败场景。
5. 实现最小功能。
6. 加入事件、日志和指标。
7. 编写集成测试和崩溃恢复测试。
8. 接入 CLI，验证不依赖 UI。
9. 接入桌面交互。
10. 更新文档、Golden Task 和迁移脚本。

禁止先做页面假数据，然后长期没有真实运行链路。

## 4. 阶段 P0：立项基线与可行性验证

### 开发目的

在正式搭建框架前验证最关键的不确定性，防止后期因模型协议、桌面框架或本地推理问题返工。

### 工作内容

#### P0.1 架构决策

- 确认 Go 模块和包边界。
- 对 Wails 稳定大版本做最小 PoC 并锁定。
- 确认 SQLite Driver、WAL、迁移工具和 FTS5 支持。
- 确认 Windows 数据目录、日志目录和凭据存储。
- 定义错误码和事件版本策略。

#### P0.2 模型协议 PoC

- 接入一个本地 Qwen OpenAI-compatible 端点。
- 接入一个远程 API Deployment。
- 测试文本、流式、Tool Call、工具结果回传、取消和超时。
- 保存原始响应样本作为 Provider 契约夹具。

#### P0.3 恢复 PoC

- SQLite 写入 Task、Event 和 Checkpoint。
- 在工具调用前、执行中和执行后模拟崩溃。
- 验证恢复时不会重复副作用。

#### P0.4 基线评测

- 建立 20 个最小 Golden Cases。
- 记录本地 Qwen 和 API 的首次基线。
- 确认评测所需指纹字段。

### 交付物

- ADR 集。
- 可运行的 Provider PoC。
- SQLite Schema v1 草案。
- Tool Call 样本夹具。
- Golden Suite v0。

### 退出标准

- 本地和 API 能通过同一接口完成一次工具闭环。
- 任务在模拟崩溃后可恢复。
- 桌面 PoC 能调用 Go Core 并接收事件。

## 5. 阶段 P1：可靠单 Agent 最小闭环

### 开发目的

完成第一个真实可用的“任务—计划—执行—验证—交付”闭环。

### 开发顺序

#### P1.1 基础存储

- Migration Runner。
- Workspace、Session、Task、Run、Event、Artifact 表。
- Event Append 和事务性物化状态。
- 数据目录与备份。

目的：在引入模型前先建立可靠事实来源。

#### P1.2 Workspace 与只读工具

- 规范化路径。
- `list_files`、`read_file`、`search_text`、`git_status`。
- 标准 ToolResult。
- 输出大小限制和 Artifact 外置。

目的：让 Reconnaissance 在没有写权限的情况下理解项目。

#### P1.3 Task Intake 与最小计划

- TaskSpec。
- 简单任务生成单步骤计划。
- 复杂任务调用 Planner。
- Plan Schema 和 DAG Validator。

目的：从第一版开始就避免无计划执行。

#### P1.4 Agent Worker

- System Contract。
- 单 Tool Call 循环。
- 最大轮次、取消、空响应和重复检测。
- Tool 参数校验与一次修复。

目的：建立面向能力有限模型的可控执行循环。

#### P1.5 写工具和审批

- `apply_patch`、受控 `write_file`、`execute_command`。
- 风险引擎。
- 用户审批票据。
- Write-ahead 和幂等键。

目的：安全引入真实副作用。

#### P1.6 验证与完成

- 文件断言、命令退出码、测试命令。
- Evidence。
- FinalReport。

目的：让“完成”由事实决定。

### P1 端到端场景

用户要求修改一个有测试的示例项目：系统侦察、计划、修改、运行测试、展示 Diff 和结果，退出重启后仍能查看完整任务。

### 退出标准

- 至少 30 个 Golden Cases 可重复执行。
- 所有副作用工具具备幂等恢复测试。
- 未授权写入和越界路径测试全部通过。
- UI 尚未完成时，CLI 已能完成完整闭环。

## 6. 阶段 P2：持久化计划、恢复与上下文治理

### 开发目的

把可以运行的 Agent 提升为可以处理中长任务的任务系统。

### 工作内容

#### P2.1 Plan Version 与局部重规划

- Plan 版本和父版本。
- 失败影响分析。
- 保留已完成步骤。
- 最大重规划次数。

#### P2.2 Checkpoint

- Step 边界自动 Checkpoint。
- 工具副作用前后 Checkpoint。
- 兼容性和迁移。
- 恢复向导。

#### P2.3 Context Compiler

- TokenCounter 接口。
- 上下文分区预算。
- 最近消息和协议边界保持。
- Artifact 摘要与片段。
- 上下文预览。

#### P2.4 大输出治理

- Tool Result 首尾保留。
- 完整内容 Artifact。
- 可选模型摘要，但保留原始内容。
- 上下文超限自动重编译。

### 退出标准

- 100 步事件流可以稳定恢复和回放。
- 上下文超过预算时不会发出无效请求。
- 重规划只影响必要步骤。
- 对运行中程序进行多点强制退出测试全部通过。

## 7. 阶段 P3：记忆、知识和 Skill

### 开发目的

让 Agent 在不读取全部历史的情况下，快速获得当前任务所需事实、决策和程序知识。

### 工作内容

#### P3.1 结构化记忆

- Memory Schema 和类型。
- 候选提取。
- 来源、置信度、作用域和时效。
- 手工固定、修正、压制和归档。

#### P3.2 本地检索

- FTS5 索引。
- 中文 n-gram。
- 向量接口与小规模精确搜索。
- RRF 融合。
- 检索调试和命中解释。

#### P3.3 项目知识索引

- 文档和代码分块。
- 路径、语言、符号和 Git Revision 元数据。
- 增量更新和失效处理。

#### P3.4 Skill

- Skill 包格式。
- 索引与按需加载。
- 工具白名单。
- 静态检查和测试。

### 退出标准

- 自动记忆全部可追溯。
- 旧决策被新决策替代时保留关系，不静默覆盖。
- 关闭向量能力后仍可使用全文检索完成基本任务。
- Skill 正文只在选中后加载。

## 8. 阶段 P4：多 Agent 与任务接力

### 开发目的

处理可以安全拆分的任务，并验证长任务在上下文切换后的连续性。

### 工作内容

- Agent Instance 持久化。
- Executor 子 Agent。
- AgentReport 与 HandoffEnvelope。
- 单层并行和资源限制。
- 父任务取消传播。
- 子 Agent 结果验证和合并。
- 接力恢复场景。

### 首批适用场景

- 两个互不依赖的只读代码分析步骤。
- 前端和后端分别分析，再由主任务汇总计划。
- 大型日志拆分分析。
- 单个 Worker 接近上下文预算时生成 Handoff，由新 Worker 继续。

### 明确限制

- 不实现递归子 Agent。
- 不实现无主持人的 Agent 群聊。
- 不让多个 Agent 同时修改同一文件。
- 不自动采用子 Agent 的完成声明。

### 退出标准

- 任务结果与串行执行等价。
- 并发取消不遗留活动模型请求和子进程。
- 新 Worker 仅凭 Handoff 和 Artifact 可以继续指定步骤。

## 9. 阶段 P5：桌面产品化

### 开发目的

把已验证的 Core 转化为普通用户可以安装和理解的软件。

### 工作内容

#### P5.1 首次启动

- 数据目录初始化。
- 本地/API 模型模式选择。
- 硬件检测和模型建议。
- Deployment 能力探测。
- 示例 Workspace 和引导任务。

#### P5.2 任务工作台

- Workspace/Session/Task 导航。
- 计划、时间线、Artifact、上下文和记忆面板。
- 审批、用户问题和任务干预。
- 运行指标与失败诊断。

#### P5.3 Model Manager UI

- Runtime、模型下载、进度、校验、启动和日志。
- Deployment 切换。
- 能力矩阵。

#### P5.4 打包与升级

- Windows 安装包。
- 数据库迁移。
- 签名和更新。
- 诊断包。

### 退出标准

- 在干净 Windows 测试机完成安装、首次启动和首个任务。
- 非开发人员能够从错误界面定位模型未启动、权限等待或测试失败。
- 应用升级后所有用户数据和任务状态保持完整。

## 10. 阶段 P6：生态与增强能力

在核心稳定后再考虑：

- MCP Server。
- 浏览器、数据库和容器专用工具。
- 可视化工作流编辑器。
- Skill 市场和签名。
- 更多桌面平台。
- 团队共享和远程 Worker。
- 高级向量索引和知识图谱。

这些能力不得绕过现有 Task、Tool、Permission、Artifact 和 Event 协议。

## 11. 测试策略

### 11.1 单元测试

- 状态迁移。
- DAG 和 Ready Set。
- Schema 校验。
- 路径规范化。
- 风险分类。
- Token 预算。
- 记忆去重和冲突。

### 11.2 契约测试

- Provider 请求响应夹具。
- Tool 输入输出。
- Skill 包。
- Event 版本。
- Handoff 和 AgentReport。

### 11.3 集成测试

- Mock Provider 完整任务。
- SQLite 事务。
- 模型流式取消。
- 工具子进程。
- Artifact 原子写入。

### 11.4 恢复测试

在以下位置强制终止：

- Plan 保存前后。
- Tool Intent 保存后、工具执行前。
- 工具执行成功后、结果保存前。
- Step 验证中。
- Checkpoint 写入中。
- 子 Agent 运行中。

### 11.5 Golden Task

- 文件问答。
- 单文件修改。
- 多文件修改。
- 测试失败修正。
- 超时命令。
- 交互式命令。
- 危险操作拒绝。
- 上下文压缩。
- 记忆召回。
- 多 Agent 接力。

## 12. Prompt 开发规范

- Prompt 进入版本控制，并带版本号。
- System Contract 与任务动态内容分离，提高缓存和稳定性。
- 每个 Prompt 有输入 Schema、输出 Schema 和失败示例。
- 不用 Prompt 代替权限和状态机。
- 修改 Prompt 必须运行相关 Golden Suite。
- 不持久化原始隐藏推理作为任务真相；只保存结构化决策和证据。

## 13. 数据库与协议迁移

- 数据库 Migration 只能向前追加，不编辑已发布脚本。
- 迁移前自动备份数据库。
- Event、Plan、ToolResult、Memory 和 Handoff 均带版本。
- Reader 至少兼容一个历史主版本。
- 无法迁移时进入只读恢复模式，而不是直接启动空库。

## 14. 发布流程

每个发布候选版本必须通过：

1. Go 单测与竞态检查。
2. 前端类型检查、单测和构建。
3. 数据库全新安装与升级迁移测试。
4. Windows 干净环境安装测试。
5. Mock Provider 全量测试。
6. 本地 Qwen 核心 Golden Suite。
7. API Deployment 核心 Golden Suite。
8. 恢复与幂等测试。
9. 权限和路径安全测试。
10. 文档与实际能力核对。

## 15. 项目管理与变更规则

- 每个迭代只承诺一个可演示纵向闭环。
- 新功能必须说明其对小模型成功率、上下文、风险或用户体验的具体价值。
- 不因参考项目已有某功能就自动纳入范围。
- 架构变更先写 ADR，再修改代码。
- 路线图功能使用“计划中/开发中/已验证”状态，禁止统一标成“支持”。
- 性能优化前先建立指标基线，避免主观优化。

## 16. 建议的首批 ADR

- ADR-0001：选择 Go 作为 Agent Core。
- ADR-0002：选择 Wails 作为桌面壳及其稳定大版本。
- ADR-0003：SQLite Event Store 与物化状态并存。
- ADR-0004：Plan 采用版本化 JSON DAG。
- ADR-0005：本地与 API 共用 Provider/Deployment 模型。
- ADR-0006：Artifact 文件存储与内容校验。
- ADR-0007：工具幂等和 Write-ahead 协议。
- ADR-0008：首期多 Agent 深度限制为一层。
- ADR-0009：Sandbox 不可用时 fail-closed。
- ADR-0010：默认本地 Runtime 和模型资源包策略。
