# SimplenessAgent 工具、安全与权限系统

## 1. 设计目标

Agent 的实际风险主要来自工具副作用，而不是自然语言回答。安全系统必须独立于模型 Prompt，确保：

- 模型只能看到和调用当前步骤允许的工具。
- 工具参数在执行前经过 Schema、路径和风险校验。
- 危险操作需要与实际参数绑定的用户授权。
- 崩溃或重试不会重复副作用。
- 沙箱不可用时不会静默退回无限制执行。
- 所有行为可以审计和解释。

## 2. 威胁模型

需要防御：

- 模型误判命令风险。
- 用户文档、网页或工具输出中的 Prompt Injection。
- 路径遍历、符号链接和大小写绕过。
- 命令拼接、Shell 转义和隐藏副作用。
- 恶意或失控 MCP Server。
- 工具输出包含密钥或隐私。
- 模型重复执行写入、提交、删除或外部请求。
- 崩溃后无法判断副作用是否已经发生。
- Skill 申请超出其声明的工具和路径。

## 3. 工具契约

每个 ToolDefinition 至少包括：

- `name`、`version`。
- `description`。
- `input_schema`、`output_schema`。
- `risk_class`。
- `side_effects`。
- `idempotency`。
- `required_capabilities`。
- `default_timeout`、`max_timeout`。
- `max_output_bytes`。
- `supports_cancel`。
- `retry_policy`。
- `sandbox_requirements`。

工具描述应短而准确，详细说明按需加载。

## 4. 标准 ToolResult

```json
{
  "version": 1,
  "tool_call_id": "call_xxx",
  "status": "SUCCEEDED",
  "summary": "测试执行完成，42 项通过",
  "data": {},
  "artifact_ids": ["art_log"],
  "evidence_ids": ["evd_test"],
  "side_effects": [
    {"type": "FILE_WRITE", "target": "...", "committed": true}
  ],
  "metrics": {
    "duration_ms": 1234,
    "output_bytes": 4096
  },
  "error": null
}
```

错误对象包括：`code`、`message`、`retryable`、`remediation`、`details_artifact_id`。

## 5. 风险等级

### READ

只读取授权数据，不改变文件、进程、网络或外部状态。

### WRITE

在 Workspace 内创建或修改可恢复内容，如应用补丁、生成文件。

### DANGEROUS

删除、覆盖重要数据、修改权限、系统设置、Git 强制操作、安装系统软件等。

### EXTERNAL_SIDE_EFFECT

发送消息、提交表单、创建远程资源、发起支付或任何影响外部系统/他人的动作。

外部副作用独立于文件危险等级，默认需要明确审批。

## 6. 风险判定

判定输入包括：

- Tool 固有风险。
- 实际参数。
- 规范化目标路径。
- 命令 AST 或分词结果。
- 是否包含管道、重定向、子 Shell、变量或通配符。
- Workspace 权限规则。
- Skill 上限。
- 用户当前审批策略。

模型提供的 `risk` 只作为提示，不作为最终结论。最终风险只能提高，不能因模型声明降低。

## 7. 权限模型

采用 Capability：

- `fs.read`
- `fs.write`
- `fs.delete`
- `process.exec.readonly`
- `process.exec.write`
- `process.exec.dangerous`
- `network.outbound`
- `git.write`
- `mcp.call:<server>:<tool>`
- `secret.use:<credential>`
- `user.prompt`

Capability 同时绑定 Scope，例如 Workspace 路径、主机、端口或 MCP Server。

## 8. 审批票据

审批对象包括：

- Tool 名称和版本。
- 规范化参数哈希。
- Task、Step、Attempt。
- 风险和副作用。
- Scope。
- 有效期和使用次数。
- 用户决定和说明。

参数、目标或 Tool 版本变化后旧票据失效。

审批范围：

- 单次。
- 当前 Step 的相同模式。
- 当前 Task。
- 当前 Workspace 会话。
- 持久规则，仅适用于低风险且用户主动设置。

## 9. 路径安全

执行前：

1. 转为绝对路径。
2. 清理 `.`、`..`。
3. 解析存在部分的符号链接/重解析点。
4. 处理 Windows 盘符和大小写。
5. 确认最终目标位于授权根内。
6. 对待创建文件验证父目录。

禁止以未解析环境变量、宽泛通配符、用户主目录符号或根目录作为递归删除/移动目标。

## 10. 文件写入

- 读取当前内容和哈希。
- 生成 Patch 或临时文件。
- 校验预期旧哈希，防止并发覆盖。
- 写入临时文件。
- 可选格式化和验证。
- 原子替换。
- 保存 Diff Artifact。

大范围删除和移动优先使用可恢复方式；无法恢复时提高风险等级。

## 11. 命令执行

### 命令描述

Tool Call 必须说明：

- 当前 Shell。
- 工作目录。
- 命令和参数。
- 环境变量白名单。
- 超时。
- 预期副作用。

### 子进程控制

- 独立进程组或 Job Object。
- stdout/stderr 分流并限制大小。
- 超时先优雅终止，再强制终止。
- 支持后台任务句柄。
- 退出码和信号标准化。

### 交互式命令

- 默认不自动猜测输入。
- 只有检测到明确提示或用户确认后发送输入。
- 密码不进入模型上下文和普通日志。

## 12. 幂等与恢复

幂等键：

`run_id + step_id + attempt + tool_call_id`

状态：

- `INTENT_RECORDED`
- `APPROVED`
- `STARTED`
- `SIDE_EFFECT_UNKNOWN`
- `SUCCEEDED`
- `FAILED`
- `CANCELLED`

恢复逻辑：

- 未 STARTED：可以安全执行。
- STARTED 但无结果：先检查外部状态。
- 已 SUCCEEDED：返回已有 ToolResult，不重复执行。
- SIDE_EFFECT_UNKNOWN：必须人工或专用恢复器确认。

## 13. Tool Output 治理

- 输出达到上限时保留首部、尾部和截断说明。
- 完整输出写入 Artifact。
- 二进制内容不直接进入模型上下文。
- 对日志进行密钥和凭据脱敏。
- Tool Output 明确标记为不可信数据，不能改变 System Contract。
- 模型摘要不能替代原始输出。

## 14. Sandbox

### 第一阶段

- 强制 Workspace 路径边界。
- 工具白名单。
- 环境变量过滤。
- 进程组和资源限制。
- 网络默认关闭或审批。

### 后续 Backend

- Windows Sandbox/受限令牌/Job Object 能力组合。
- Linux bubblewrap/namespace。
- Docker/WSL 隔离。

每个 Backend 报告真实能力矩阵。需要某项隔离但 Backend 不支持时，操作被拒绝或要求用户明确切换模式，不能自动 fail-open。

## 15. MCP 安全

- 首次连接展示 Server 来源、传输方式和工具列表。
- Tool Schema 缓存带版本和哈希。
- 每个 MCP Tool 单独授权。
- 限制返回大小、超时和并发。
- Stdio Server 作为受控子进程启动。
- 网络 MCP Server 配置主机白名单和凭据引用。
- MCP 返回内容视为不可信数据。

## 16. Skill 安全

- Skill 声明工具和 Scope 上限。
- 导入时检查脚本、路径和外部依赖。
- 锁定/签名 Skill 不允许 Agent 自动修改。
- Skill 指令不能提升系统权限。
- Skill 引用文件按需读取，并经过同一 Workspace 策略。

## 17. Secret 管理

- API Key 和 Token 使用系统凭据库。
- 模型上下文只获得“可使用某凭据”的能力，不获得明文。
- 工具通过凭据句柄注入请求头或进程环境。
- 日志和 Artifact 经过 Redaction。
- 诊断包默认不含模型请求正文和敏感文件。

## 18. 审计

审计事件包括：

- 权限请求、批准、拒绝和撤销。
- 危险和外部副作用 Tool Call。
- 越界访问尝试。
- Secret 使用但不记录明文。
- Sandbox 降级或不可用。
- MCP/Skill 安装和版本变化。
- 数据删除与导出。

## 19. 首批工具开发顺序

1. Tool Registry、Schema 和 Mock Tool。
2. 只读文件工具。
3. Artifact 读取工具。
4. Patch 写入工具。
5. 前台命令工具。
6. 后台命令与输出收集。
7. Git 只读工具。
8. 用户询问工具。
9. Skill 加载。
10. MCP Client。

每加入一个工具必须同时增加风险表、契约测试、输出限制和恢复测试。

## 20. 验收场景

- 模型把删除命令标记为 READ，系统仍要求危险审批。
- `../`、符号链接、Windows 大小写和重解析点不能越界。
- 批准后 Tool 参数变化会重新审批。
- 工具执行后程序崩溃，恢复不重复修改。
- MCP 返回 Prompt Injection 不改变 System Contract。
- Sandbox 缺失时需要强隔离的命令被拒绝。
- 日志和诊断包中不出现测试 API Key。
