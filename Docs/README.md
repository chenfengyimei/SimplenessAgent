## 1. 文档目的

本目录用于固定 SimplenessAgent 的项目目标、架构边界、功能范围、开发顺序和验收标准，避免项目在长期开发中逐渐变成“功能很多但核心不可靠”的聊天工具。

本项目的核心定位是：

> 面向本地及 API 模型的、规划优先、上下文受控、可验证、可恢复、可接力的本地 Agent 任务运行时。

第一参考模型为 `Qwen3.6-35B-A3B`。框架不会绑定单一模型，而是以该模型作为能力下限和重点验收对象，确保能力有限或上下文成本较高的模型也能稳定完成真实任务。

## 3. 核心术语

| 术语 | 定义 |
|---|---|
| Workspace | 用户授权 Agent 工作的本地目录及其配置边界 |
| Session | 用户与系统的交互会话，负责展示消息，不等同于任务状态 |
| Task | 一个具有目标、约束和验收条件的可执行任务 |
| Run | Task 的一次实际运行实例；同一 Task 可以重试或从 Checkpoint 恢复 |
| Plan | 版本化、结构化、可校验的步骤 DAG，不是普通 Markdown 计划 |
| Step | Plan 中最小可调度工作单元，具有输入、输出、工具和验收条件 |
| Attempt | 某个 Step 的一次执行尝试 |
| Agent Worker | 接收单一目标、有限上下文和工具白名单的模型执行单元 |
| Provider | 模型协议适配器，如 OpenAI-compatible 或 Anthropic-compatible |
| Deployment | 一个可调用的模型部署实例，如本地 llama.cpp 或远程 API |
| Model Profile | 针对特定模型及角色的参数、能力和约束配置 |
| Tool | 由运行时控制的确定性外部能力，如读取文件、执行命令 |
| Skill | 可复用的任务流程、约束、模板和工具白名单包 |
| Artifact | 文件、补丁、日志、报告等可寻址任务产物 |
| Memory | 从事件和产物中提炼出的结构化、可检索信息 |
| Context Compiler | 按当前步骤和 Token 预算构造最小充分上下文的组件 |
| Checkpoint | 可用于崩溃恢复和 Agent 接力的持久化任务快照 |
| Handoff | Agent 之间的结构化交接包，而不是完整聊天记录 |

## 4. 已确定的架构决策

以下为当前立项基线，后续变更必须记录原因：

- 核心运行时使用 Go，桌面壳使用 Wails + Vue 3 + TypeScript。
- SQLite 是默认且必须可单机运行的数据存储，不要求用户安装外部数据库。
- 模型通过 Provider/Deployment 接口接入，本地和 API 共用同一套 Agent Core。
- 复杂任务必须先形成结构化计划，再进入执行。
- 确定性调度器掌握任务状态，模型不能直接篡改运行状态。
- 所有完成状态必须有可检查证据。
- 原始事件和 Artifact 不因摘要或压缩而丢失。
- 多 Agent 第一阶段限制为单层，不允许递归代理网络。
- 权限和风险由运行时判定，不能只相信模型声明。
- UI 是核心运行时的客户端，不能承载不可恢复的 Agent 业务状态。
